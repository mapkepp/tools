## Что необходимо сделать в интерфейсах владельца

### A. GitHub Pages — ОБЯЗАТЕЛЬНО

1. Открыть https://github.com/mapkepp/tools/settings/pages
2. Source: **Deploy from a branch**.
3. Branch: **main**; Folder: **/(root)**.
4. Нажать **Save**, затем проверить https://mapkepp.github.io/tools/.
5. Проверить на Safari iPhone доступность/выполнение сайта.

По состоянию на подготовку Pages по новому URL выдавал HTTP 404. В подключённом GitHub-инструменте нет операции настройки Pages.

### B. Яндекс OAuth — ОБЯЗАТЕЛЬНО для безопасного входа пользователей

Открыть https://oauth.yandex.ru/client/new/id/ , войти в собственный аккаунт Яндекса и зарегистрировать тип **«Для авторизации пользователей»** (не «Для доступа к API/отладки»). Указать понятное название `Mapkepp Tools — Умный дом`, контактную почту владельца и веб-платформу.

Планируемый Redirect URI: `https://mapkepp.github.io/tools/oauth/callback.html`. **Не запускать реальную авторизацию до реализации и проверки callback.** Если точное имя маршрута изменится при разработке, изменить Redirect URI в настройках приложения.

Запросить только доступы **iot:view** (перечень домов/комнат/устройств) и **iot:control** (управление), без ненужных прав персонального профиля.

Передать разработчику **только Client ID (идентификатор приложения)**. **Не отправлять Client Secret, пользовательский OAuth-токен, коды подтверждения, пароли или сессионные cookies ни в GitHub, ни в публичные обсуждения.**

Документация:
- https://yandex.ru/dev/id/doc/ru/register-auth
- https://yandex.ru/dev/id/doc/ru/codes/code-url (PKCE S256, state)
- https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-user-info
- https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-protocol

**Статус:** OAuth вход, безопасный обмен кода на токен и адаптация к Apple Shortcuts пока **НЕ РЕАЛИЗОВАНЫ**. Создание OAuth-приложения только подготавливает доступ; не означает, что сайт уже может подключить Яндекс ID.

### C. Донаты — НЕОБЯЗАТЕЛЬНО

Выбрать собственный легальный способ добровольных переводов, ознакомиться с условиями платёжного сервиса (включая статус физлица, налогообложение и ограничения сервиса), сформировать публичную ссылку. Прислать **только адрес страницы пожертвования**, не реквизиты входа в банк. До проверки сайт не принимает платежи, а кнопка является заглушкой. Нельзя делать платные функции, выгоды за перевод или обещать услугу в обмен.

## Модель приватности на целевой архитектуре

1. Яндекс OAuth авторизует пользовательскую учётную запись через официальную страницу.
2. Секрет доступа должен оставаться в контексте пользовательского устройства; не отправлять OAuth-токен и `client_secret` на GitHub Pages или сервис подписи.
3. Приложение-команда на iPhone получает `GET /v1.0/user/info` локально с токеном и формирует минимальный экспорт дерева без токенов.
4. Статический веб-конструктор отображает дерево и создаёт команду с выбранными действиями.
5. При необходимости подпись выполняется над **шаблоном без токена**.
6. На iPhone в отдельном приватном действии/помощнике пользователь может задать токен один раз для использования несколькими командами (требует реализации и тестирования).

Это целевая архитектура, **не** подтверждение готовности функций.
