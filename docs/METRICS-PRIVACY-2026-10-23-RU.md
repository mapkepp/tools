# Mapkepp Tools — анонимные счётчики и аудит приватности (23.10.2026)

## Разрешённое изменение

- На главной и в экспериментальной студии шапка: «Бесплатно · Без регистрации by Mapkepp», небольшая кнопка «💜 Поддержать» с прокруткой до существующих Т-Банка и ЮMoney. Кнопка не перезаписывает hash с QR-конфигурацией.
- В нижней части обеих страниц показаны приблизительные суммарные просмотры и действия с конструктором, а также значения конкретной страницы. Начальная статистика — с момента подключения этого счётчика, предыдущая посещаемость не восстанавливается.
- Для просмотров — только одна запись на страницу на вкладку примерно в 30 минут; для действий — нажатия ключевых кнопок с защитой от повторных кликов в течение 8 секунд. Это не уникальные посетители, не число успешных подписей и не достоверная защита от накрутки.

## Архитектура данных

- Браузерский скрипт: `studio/metrics.js` и изолированная версия главной `studio/frozen-2026-10-23/metrics.js`.
- Supabase Edge `site-metrics`, адрес без авторизованного аккаунта; CORS строго для `https://mapkepp.github.io`, ограничение размера и двух полей `{page,event}`, разрешены только `page:home|studio` и `event:visit|use`.
- Таблица `public.mapkepp_site_metrics`: только `page,visits,uses,updated_at`. Нет IP, OAuth, устройства, имени, QR, URL, cookies, идентификатора браузера или профиля.
- RLS включен; роли `anon` и `authenticated` не имеют SELECT/UPDATE или доступа к RPC; сервер использует секретный ключ через Edge. PostgreSQL `mapkepp_count_site_event` увеличивает число атомарным UPDATE и допустим только для service_role.
- Браузер хранит в sessionStorage только локальный timestamp повторного посещения. Для метрик не требуется cookie и не добавляется сторонний аналитический скрипт.
- Провайдеры инфраструктуры могут сохранять собственные журналы сетевых обращений, даже если Mapkepp не собирает эти поля в таблицу метрик.
- Анонимный публичный счётчик потенциально можно искусственно увеличить: проверка Origin не является криптографической аутентификацией. Поэтому значения в интерфейсе явно маркированы как оценочные.

## Аудит утечек: факты и границы

- Сканирование основных публичных HTML, JavaScript и серверных файлов, OAuth callback и документации на типовые шаблоны OAuth bearer, служебных секретов и PEM: **PASS на проверенном наборе**, совпадений не найдено. Это статический анализ, а не доказательство отсутствия секретов в каждом файле/историческом коммите.
- Метрики отправляют только два разрешённых значения. Серверная валидация отклоняет произвольные поля включая `device_name`; URL запроса не содержит пользовательских значений, cookies не пересылаются; в базе сохраняются только суммы.
- Обработчики Яндекса получают токен исключительно для запросов API с согласия пользователя; токен временно находится в поле и sessionStorage вкладки при OAuth, что делает его потенциально доступным вредоносным расширениям и скриптам происхождения страницы. Абсолютную защиту от компрометации браузера обещать нельзя.
- Импортированный перечень устройств и локально сохранённый JSON/IndexedDB содержит имена и ID, но не OAuth-токен. Пользователь контролирует сохранение и удаление.
- Публичная QR-ссылка включает имя/ID выбранного устройства, но не OAuth-токен; адресат ссылки сможет видеть эти значения. При стандартной подписи Shortcuty получает шаблон с названием и ID, **без токена**. Опасный дополнительный режим со встроенным токеном имеет отдельное явное согласие и существенно повышает риск.
- CSP в GitHub Pages нельзя корректно добавить `frame-ancestors` через HTML meta, а чрезмерно строгая CSP может сломать официальный SDK Яндекс ID; не делать фиктивных изменений ради отчёта. На страницах добавлен `referrer=no-referrer` и для метрик `credentials=omit`.
- Пользовательский Safari/iOS и реальная авторизация остаются `NOT_TESTED` для новых страниц после этих изменений; облачный браузерный сценарий, внешняя подпись синтетического Shortcuts и отдельная серверная проверка метрик — `PASS` по GitHub Actions.

## Дополнение 23.10.2026 — приблизительное число уникальных браузеров

Новый показатель рядом с посещениями и действиями: «≈ уникальных браузеров» отдельно для `home`, `studio` и для всего сайта. Общий показатель не суммирует два отдельных: при переходе с главной в студию тот же браузер увеличивает общий счётчик только при первом посещении любого из двух разделов. Исторические уникальные до включения не восстановить. Один человек с телефона и ПК считается дважды, разные люди в одном браузере — один раз, очистка localStorage позволяет повторный подсчёт; одновременные вкладки и искусственные запросы тоже ограничивают точность.

**Конфиденциальность:** на сервер никогда не отправляется идентификатор посетителя, токен, IP, fingerprint, URL или список устройств. Для однократного подсчёта браузер записывает исключительно локальные отметки `mapkepp.metrics.unique.site.v1` и `mapkepp.metrics.unique.page.{home|studio}.v1` в localStorage (с промежуточным статусом `pending` на короткий срок), ни одна из этих отметок не синхронизируется. Если сохранение в браузере запрещено, уникальное посещение не отправляется. В Supabase `mapkepp_site_metrics.unique_browsers` хранит число для каждой страницы, а `mapkepp_site_unique_totals.unique_browsers` — общую сумму. Не создаётся таблица с посетителями. Встраиваемые сторонние аналитические скрипты не добавляются.

**Применение Harness², Hermes, канонов**: сохранена точка отката `backup/pre-unique-counter-2026-10-23` (HEAD `7c165935bcfd8453c717081ef24f8f62bc42fcbc`). Изменена только изолированная аналитика и текст статистики на обеих страницах; сохранён остальной код конструктора, подписи, OAuth, QR и локальных устройств. Тесты проверяют два разных раздела в одном браузере, отсутствие повторного учёта при перезагрузке, RLS закрытых таблиц, запрет идентификаторов в API и атомарное увеличение счётчика с последующим откатом тестовой транзакции.
