## Baseline / воспроизведённые проблемы

- До исправления подпись отправлялась скрытой HTML multipart-формой на `sign.shortcuty.app` в новую вкладку: статус успешной подписи/сохранения не контролировался.
- При авторизации с QR/ссылки существовал риск потерять выбранную конфигурацию/попасть на экран автоматической загрузки, тогда как получателю нужен только доступ к токену и готовой команде.
- Несколько пользователей потенциально одновременно загружают инвентарь; прямой browser fetch Яндекс IoT API ограничен CORS, API `GET /v1.0/user/info` содержит весь дом. До уменьшения ответа наблюдались оборванные HTTP-тела. Текущее производство использует stateless сегменты с SHA-256; пользовательский end-to-end успех необходимо подтверждать отдельно.

## Изменения Studio после заморозки

1. `studio/signer.js` + `supabase/functions/shortcut-sign/`: ограниченный по Origin и размеру подписывающий relay. Принимает **только** XML с плейсхолдером `YANDEX_OAUTH_TOKEN`, направляет во внешний Shortcuty API, проверяет `AEA1` и хеши, возвращает бинарный файл. Хранение файлов и токенов не предусмотрено.
2. В Safari /studio показывает самостоятельную ссылку на подписанный файл и кнопку `navigator.share({files})` при наличии платформенной поддержки. Импорт файла на реальном iPhone всё ещё `NOT_TESTED`.
3. `studio/share.js` и `studio/app.js`: сохраняют нетокенную конфигурацию в `sessionStorage` при авторизации, восстанавливают при OAuth callback с `state`, не запускают автоматический импорт вместо восстановленного QR-сценария. Токен по-прежнему временный.
4. Индивидуальные HTTP-запросы на сервере stateless; данные разных пользователей не помещаются в общий кэш/таблицу. Порядок запросов в браузере последовательный; сервер умеет обслуживать независимые обращения. Это **не** доказательство бесконечной ёмкости Free-tier или отсутствия лимитов API Яндекса.
5. Дополнительная локальная альтернатива — подписанная `ios/Yandex_Home_Discovery.shortcut` и ручной импорт JSON; получение JSON в Safari через Web Fetch прямо с Yandex невозможно гарантировать из-за CORS. Реальный iPhone workflow `NOT_TESTED`.

В отдельном браузерном тесте следует подтвердить работу демонстрации, сохранение/экспорт/импорт, восстановление и удаление кеша. ## Доставка подписанных файлов по частям — 23.10.2026

Базовая проблема подтверждена реальными пользовательскими trace: Shortcuty выдавал HTTP 200 и сервер получал 22–23 КБ подписанного AEA1 примерно за 3–5 секунд, а браузер зависал на чтении HTTP-тела. Новый механизм: подготовка подписи, AES-GCM шифрование файла на сервере, временная запись в закрытой таблице с RLS на 10 минут, фрагменты по 1536 символов base64, локальная сборка/расшифровка браузером, SHA-256, возврат .shortcut и явное удаление, дублируемое cron-очисткой. Пользовательский OAuth-токен в этом процессе не участвует. В логах page=home|studio + trace UUID, фазы и метрики каждой части. Стартовая доказательная проверка живого backend: 20 частей, 22901 байт, AEA1, совпадение SHA-256, удаление, около 16 секунд. Статус Safari/iPhone — NOT_TESTED. После дополнительного браузерного прогона устранён баг ArrayBuffer: crypto.subtle.decrypt возвращает ArrayBuffer, поэтому нельзя читать поле .buffer как у Uint8Array. Контрольный SHA главной: `00cd60042a776408fb00461be1667744d487a005`. При недоступности проверки браузера нельзя заявлять PASS по одному серверному тесту.
