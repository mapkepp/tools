# Автоматическая загрузка Яндекс Умного дома — реализация

**Дата:** 22.10.2026. **Основной код:** https://github.com/mapkepp/tools

## Готовый интерфейс

Адрес: https://mapkepp.github.io/tools/studio/

1. Пользователь нажимает «Войти через Яндекс». Перед переходом генерируется случайный OAuth `state`, сохраняемый только во временной памяти вкладки.
2. Яндекс выдаёт токен через Redirect URI `https://mapkepp.github.io/tools/oauth/callback.html`.
3. Callback сверяет `state`, удаляет параметр `access_token` из адресной строки и временно передаёт токен обратно конструктору в рамках той же вкладки через `sessionStorage`. После чтения ключ удаляется.
4. Пользователь также может самостоятельно вставить токен в скрытое поле (без сохранения в `localStorage`, cookie или базе данных).
5. После явного согласия на передачу токена обработчику выполняется **один** HTTPS POST к серверному обработчику.
6. Обработчик запрашивает `GET https://api.iot.yandex.net/v1.0/user/info` с заголовком `Authorization: Bearer`, возвращает ответ в браузер и не сохраняет токен.
7. На странице есть индикатор этапов («Подключение → Запрос → Проверка → Построение → Готово») и понятные ошибки: неверный токен, сеть/VPN, таймаут.
8. Данные отображаются по домам/комнатам; группы и сценарии отдельно. Сценарии не имеют подтверждённой привязки к дому или комнате в ответе Яндекса.
9. Генерация Apple Shortcut и загрузка тестировались на синтетических ID. При подписи на Shortcuty **токен не передаётся**, но ID выбранного устройства и действие доступны сервису подписи.

## Важный блокер перед реальной загрузкой

**Серверный обработчик ещё НЕ РАЗВЁРНУТ.** Статический хостинг GitHub Pages не выполняет серверные функции, а API Яндекса не разрешает прямой CORS-запрос с GitHub Pages. Поэтому вставка токена пока только заполняет интерфейс: сайт не должен отправлять секреты на несуществующий сервер, не должен пользоваться открытыми CORS-прокси и не должен выдавать демонстрационные данные за реальные.

Подготовлено:
- `api/yandex-home.js` — read-only HTTPS прокси для Vercel Functions (метод POST, фиксированный upstream Яндекса, ограничение размера, CORS только https://mapkepp.github.io, нет хранилища и логирования секретов).
- `studio/backend-config.js` — публичный URL развёрнутого обработчика; сейчас намеренно пустой. Токены туда **никогда** не записывать.
- `oauth/callback.html` — обработчик возврата с OAuth state.
- `studio/app.js` — авто-получение токена и загрузка с видимым прогрессом, если backend URL настроен.
- При отсутствии backend сайт честно показывает предупреждение и предлагает получение JSON на iPhone.

### Как активировать

**Вариант: бесплатный Vercel Hobby**, при условии соблюдения действующих лимитов Vercel и успешного подключения аккаунта владельца:

1. Подключить свой аккаунт Vercel к публичному репозиторию `mapkepp/tools`. Не публиковать секреты и токены; приложение OAuth использует публичный Client ID, но секретный ключ ему не нужен.
2. Deploy репозитория как проект с Vercel Function `api/yandex-home.js`. Проверить, что URL вида `https://<ваш-домен>.vercel.app/api/yandex-home` отвечает `OPTIONS` с Origin `https://mapkepp.github.io` как 204.
3. Проверить POST на тестовом синтетическом токене: сервер должен вернуть 401 от Яндекса (без содержимого токена в ответе/логах) либо конкретную сетевую ошибку, но **не** 404/500.
4. В репозитории `mapkepp/tools` прописать фактический проверенный HTTPS URL в `studio/backend-config.js`.
5. Убедиться, что GitHub Actions Pages автоматически обновил сайт. Выполнить end-to-end тест с личным токеном на устройстве пользователя **без отправки токена в чат**.
6. Проверить поддержку всех реально возвращаемых типов, поиск, несколько домов, группы, активные/неактивные сценарии и генерацию реальных команд iOS.

**Не путать:** GitHub Pages размещает публичный интерфейс; Vercel должен обслуживать только запрос `/api/yandex-home`. Исходники Vercel Function в GitHub — ещё не развёрнутый backend.

## Приватность и ограничения

- При автоматической загрузке токен **передаётся** через HTTPS в управляемый владельцем серверный обработчик и далее в Яндекс. В клиентском JavaScript поле видимо скриптам текущего origin. Обещание «токен вообще не покидает телефон» для этого режима было бы неверным.
- Приложение не пишет токены в БД, GitHub, console.log, localStorage или cookies. Облачный провайдер может иметь технические журналы и отдельные условия обработки.
- Используются только доступы `iot:view` и `iot:control`, необходимые для чтения и последующего управления. Сам API-обработчик только читает `/user/info`, не выполняет действия над домом.
- Получение токена через OAuth implicit/hash соответствует ранее подготовленному приложению, но для следующего релиза предпочтительно рассмотреть OAuth authorization code + PKCE и отказ от передачи bearer-токена через JavaScript.
- По умолчанию ничего не сохраняется между сеансами. Закрытие/сброс вкладки удаляет токен из временной памяти, но пользователь должен также очистить поле при завершении работы.
- Копии исходной команды для iPhone по-прежнему требуют ввода токена на самом iPhone. Единое безопасное хранилище токенов для Apple Shortcuts не реализовано.
- Никакой оплаты за функциональность, преимущества или лимитов для недонатящих. ЮMoney и Т-Банк только добровольная поддержка.

## Критерии приёмки

| Проверка | Статус |
|---|---|
| Ручной ввод токена, скрытое поле, очистка | PASS (тест браузера) |
| OAuth state и автоперенос тестового токена без URL-утечки | PASS (браузер, синтетический токен) |
| Этапы прогресса и построение дерева после тестового ответа | PASS (mock API) |
| Backend: проверка CORS, валидации, правильного запроса к Яндексу | PASS (модульный mock) |
| Backend реально развёрнут и доступен из браузера | **FAIL / NOT_DEPLOYED** |
| Авторизация и получение данных реального пользователя | **NOT_TESTED** |
| Подписанная команда на реальном iPhone управляет устройством | **NOT_TESTED** |

Официальный API: https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-user-info
